# 단일 연결 리스트: 코드와 그림으로 이해하기

> 2026-10-30 실행 검토: cpp의 중복 클래스 정의를 제거하고 다음 노드 멤버 이름을 헤더의 `next_`로 통일했습니다. `GetAt`은 빈 리스트·음수·범위 밖 인덱스에서 -1을 반환하도록 수정했습니다. 아래 원본 코드와 오류 설명 중 이 수정에 해당하는 부분은 수정 전 동작을 설명합니다.

이 문서는 같은 폴더의 `ptrlist.cpp`, `ptrlist.h`를 설명합니다. 각 함수의 코드 블록은 현재 파일에서 가져온 실제 코드입니다. `/* ... */` 안에 있는 과거 버전은 실행되지 않으므로, 실행되는 함수들을 중심으로 설명합니다.

## 1. 먼저 전체 구조 이해하기

이 리스트는 정수를 **오름차순으로 저장**합니다. `Insert(5)`, `Insert(2)`, `Insert(3)` 순서로 넣어도 최종 순서는 `2 → 3 → 5`입니다.

노드는 값과 다음 노드의 주소를 함께 담은 작은 객체입니다. `[2]`라고 줄여 그리더라도 실제로는 `data_ = 2`와 `next_`가 함께 들어 있습니다.

```text
main()의 변수       list 객체               node 객체들

lst -------------> +------------+
                   | lst_ ------+----> [2 | next_] ---> [3 | next_] ---> [5 | 0]
                   +------------+
```

`lst`와 `lst_`는 이름이 비슷해도 서로 다릅니다.

| 이름 | 자료형 | 역할 |
| --- | --- | --- |
| `lst` | `list *` | main에서 리스트 관리 객체를 가리킨다. |
| `lst_` | `node *` | 그 객체 안에서 첫 노드를 가리킨다. |
| `next_` | `node *` | 각 노드 안에서 다음 노드를 가리킨다. |
| `ptr` | `node *` | 함수 안에서 노드를 찾아다니는 임시 포인터다. |
| `data_` | `int` | 실제 저장된 정수 값이다. |

`node *ptr`의 `*`는 포인터 선언입니다. `ptr->data_`는 ptr가 가리키는 노드의 값을 읽습니다. `ptr = ptr->next_`는 다음 노드의 주소를 ptr에 넣습니다. 노드를 옮기거나 복사하는 동작이 아닙니다.

이 코드에서 포인터 값 `0`은 다음 노드가 없다는 뜻입니다. 정수 데이터 `0`도 저장할 수 있는데, `data_ = 0`과 `next_ = 0`은 서로 다른 의미입니다. 현대 C++에서는 이런 널 포인터를 `nullptr`로 쓰기도 합니다.

```text
ptr가 이동하기 전: lst_ ---> [2] ---> [3] ---> [5] ---> 0
                            ^
                            ptr

ptr가 이동한 후:   lst_ ---> [2] ---> [3] ---> [5] ---> 0
                                    ^
                                    ptr
```

`ptr`를 움직여도 `lst_`는 여전히 첫 노드를 가리킵니다. 두 포인터가 저장하는 주소는 각각 따로 바꿀 수 있습니다.

## 2. node 생성자: 값과 다음 노드 주소를 저장

```cpp
    node(int d, node *n = 0)
    {
        next_ = n;
        data_ = d;
    }
```

생성자는 `new node(...)`로 노드를 만들 때 실행됩니다. 첫 인수 d는 값이고, 두 번째 인수 n은 다음 노드 주소입니다. n을 생략하면 기본값 0을 사용합니다.

```text
new node(2, 0)

+----------------+
| data_ = 2      |
| next_ = 0      | ---> 다음 노드 없음
+----------------+
```

이미 `[5]` 노드가 있고 그 주소를 p가 저장한다면 `new node(3, p)`는 다음처럼 새 노드를 만듭니다.

```text
새 노드 [3 | next_] ---> 기존 노드 [5 | ...]
```

기존 `[5]`를 새로 만드는 게 아닙니다. 새 `[3]`의 next_에 기존 노드의 주소를 저장하는 것입니다.


## 3. list 생성자: 빈 리스트 만들기

```cpp
list::list()
{
    lst_ = 0;
    // size_= 0;
}
```

리스트 관리 객체를 만들었지만 아직 노드는 만들지 않은 상태입니다.

```text
list 객체
+----------+
| lst_ = 0 | ---> 첫 노드 없음
+----------+
```

`lst_ = 0`은 “첫 번째 값이 0이다”가 아니라 “아직 첫 번째 노드가 없다”는 뜻입니다. 이후 첫 삽입에서 lst_가 실제 노드의 주소를 받습니다.


## 4. GetSize(): 노드를 따라가며 개수 세기

```cpp
int list::GetSize()
{
    node *ptr = lst_;
    int count = 0;
    while (ptr != 0)
    {
        ptr = ptr->next_;
        count++;
    }
    return count;
}
```

`ptr`를 첫 노드에 놓고, 노드 하나를 지날 때마다 count를 1씩 올립니다. 이 구현은 개수를 멤버 변수에 저장하지 않으므로 호출할 때마다 전체 노드를 방문합니다.

```text
리스트: [2] ---> [3] ---> [5] ---> 0

시점              ptr가 가리키는 대상    count
시작              [2]                   0
첫 반복 후        [3]                   1
두 번째 반복 후   [5]                   2
세 번째 반복 후   0                     3
반복 종료                               return 3
```

반복문 안에서 먼저 ptr를 이동하고 그다음 count를 올리지만, 반복에 들어왔을 때 존재했던 노드 하나를 센다고 이해하면 됩니다.

빈 리스트는 처음부터 ptr가 0이므로 반복하지 않고 0을 반환합니다. 마지막 노드의 next_가 0이므로 마지막 이동 후 ptr도 0이 됩니다. 배열의 범위를 넘어가는 접근과는 다릅니다.


## 5. GetAt(index): 순서로 값 읽기

```cpp
int list::GetAt(int index)
{
    node *ptr = lst_;
    for (int i = 0; i < index; i++)
    {
        if (ptr == 0)
            return -1;
        ptr = ptr->next_;
    }
    return ptr->data_;
}
```

인덱스는 0부터 시작합니다. index번 next_를 따라 이동한 뒤 그 노드의 data_를 반환합니다.

```text
인덱스:       0       1       2
lst_ ------> [2] ---> [3] ---> [5] ---> 0

GetAt(2)
시작: ptr -> [2]
i=0: ptr -> [3]     1번 이동
i=1: ptr -> [5]     2번 이동
반환: 5
```

`GetAt(0)`은 이동하지 않고 첫 노드의 값을 읽습니다. 배열처럼 바로 `arr[index]`에 접근할 수 없어서 첫 노드부터 걸어가야 합니다.

### 현재 코드의 범위 검사에서 주의할 점

원본은 반복문 **안에서만** ptr가 0인지 검사합니다. 위처럼 노드가 3개일 때 `GetAt(3)`은 다음처럼 진행됩니다.

```text
[2] -> [3] -> [5] -> 0
                     반복이 끝난 뒤 return ptr->data_ 실행
                     하지만 ptr는 0이므로 잘못된 접근!
```

빈 리스트의 `GetAt(0)`도 같은 문제가 있습니다. 음수 인덱스는 반복하지 않고 첫 값을 반환하거나, 빈 리스트라면 잘못된 접근을 합니다. 따라서 모든 잘못된 인덱스에서 안전하게 -1을 반환하는 함수는 아닙니다.

학습용 개선 예시는 아래와 같습니다. 이 예시는 설명용이며 원본 파일에 적용한 코드는 아닙니다.

```cpp
int list::GetAt(int index)
{
    if (index < 0)
        return -1;
    node *ptr = lst_;
    for (int i = 0; i < index && ptr != 0; i++)
        ptr = ptr->next_;
    if (ptr == 0)
        return -1;
    return ptr->data_;
}
```

다만 -1 자체도 저장 가능한 값이므로, 반환된 -1만으로 실패와 실제 데이터 -1을 구별할 수 없다는 한계는 남습니다.


## 6. Index(key): 값이 있는 위치 찾기

```cpp
int list::Index(int key)
{
    node *ptr = lst_;
    int idx = 0;
    while (ptr != 0)
    {
        if (ptr->data_ == key)
            return idx;
        ptr = ptr->next_;
        idx++;
    }
    return -1;
}
```

GetAt이 “몇 번째 값이 무엇인가?”를 묻는다면, Index는 “이 값이 몇 번째인가?”를 묻습니다. ptr는 노드를 가리키고 idx는 그 노드의 인덱스를 나타냅니다.

```text
Index(5)

단계     ptr     idx    비교
시작     [2]      0     2 == 5 ? 아니오
이동     [3]      1     3 == 5 ? 아니오
이동     [5]      2     5 == 5 ? 예 -> return 2
```

없는 값을 찾으면 끝까지 이동합니다.

```text
Index(9): [2] -> [3] -> [5] -> 0
                               반복 종료 -> return -1
```

반복 조건에서 ptr가 0인지 먼저 확인하므로 없는 노드의 data_를 읽지 않습니다. 중복 값이 있다면 앞에서 처음 발견한 노드의 인덱스를 반환합니다.


## 7. Insert(item): 정렬된 위치에 새 노드 연결

```cpp
void list::Insert(int item)
{
    if (lst_ == 0)
    {
        lst_ = new node(item, 0);
        return;
    }
    if (item < lst_->data_)
    {
        lst_ = new node(item, lst_);
        return;
    }
    node *ptr = lst_;
    while (ptr->next_ != 0 && ptr->next_->data_ < item)
    {
        ptr = ptr->next_;
    }
    ptr->next_ = new node(item, ptr->next_);
}
```

이 함수의 핵심은 기존 값들을 이동시키는 대신 **next_에 저장된 주소를 바꾸는 것**입니다. 세 가지 경우로 나누어 봅시다.

### 경우 A: 빈 리스트에 Insert(2)

```text
전: lst_ ---> 0

new node(2, 0)으로 노드 생성
그 노드의 주소를 lst_에 저장

후: lst_ ---> [2] ---> 0
```

노드 자체가 lst_인 것은 아닙니다. lst_는 새 노드의 주소를 저장하는 변수입니다.

### 경우 B: [3] -> [5] 앞에 Insert(2)

```text
전: lst_ ---> [3] ---> [5] ---> 0

1. new node(2, lst_) 생성
   새 [2]의 next_에 기존 첫 노드 [3]의 주소를 저장

   새 [2] ---> [3] ---> [5] ---> 0
               ^
               lst_ (아직 기존 시작점)

2. 새 노드 주소를 lst_에 대입

후: lst_ ---> [2] ---> [3] ---> [5] ---> 0
```

`lst_ = new node(item, lst_)`의 오른쪽에서 사용하는 lst_는 기존 첫 노드의 주소입니다. 새 노드가 만들어진 다음 왼쪽 lst_에 새 주소가 저장되므로 기존 리스트를 잃지 않습니다.

### 경우 C: [2] -> [5] 사이에 Insert(3)

while은 현재 노드의 값이 아니라 **다음 노드의 값**을 검사합니다. 새 노드를 연결할 직전 노드에 ptr를 두려는 목적입니다.

```text
전: lst_ ---> [2] ----------> [5] ---> 0
               ^
               ptr

ptr->next_->data_는 5
5 < 3 은 거짓이므로 [2]에서 멈춤

1. 새 노드의 next_를 기존 다음 노드 [5]로 설정

             [2] ----------> [5] ---> 0
                              ^
             새 [3] ----------+

2. [2]의 next_를 새 [3]으로 변경

후: lst_ ---> [2] ---> [3] ---> [5] ---> 0
```

이 두 동작을 한 줄로 표현한 것이 `ptr->next_ = new node(item, ptr->next_)`입니다. 오른쪽의 기존 next_를 새 노드에 먼저 저장한 뒤, 왼쪽 next_를 새 노드로 바꿉니다.

### 맨 뒤에 Insert(7)

```text
전: [2] -> [3] -> [5] -> 0
                  ^
                  ptr (next_가 0이므로 정지)

후: [2] -> [3] -> [5] -> [7] -> 0
```

`&&`는 왼쪽 조건이 거짓이면 오른쪽을 실행하지 않습니다. 그래서 next_가 0일 때 `ptr->next_->data_`를 읽지 않습니다.

같은 값도 삽입할 수 있습니다. 다만 첫 노드와 같은 값은 첫 노드 뒤에 들어가고, 그보다 큰 중복 값은 탐색 중 만난 기존 같은 값 앞에 들어갈 수 있습니다. 값의 오름차순은 유지하지만, 같은 값들 사이의 삽입 순서를 일관되게 보존하는 코드는 아닙니다.


## 8. Delete(key): 연결을 건너뛰게 한 뒤 노드 해제

```cpp
void list::Delete(int key)
{
    node *ptr = lst_;
    if (lst_ == 0)
        return;
    if (lst_->data_ == key)
    {
        lst_ = lst_->next_;
        delete ptr;
        return;
    }
    while (ptr->next_ != 0 && ptr->next_->data_ != key)
    {
        ptr = ptr->next_;
    }
    if (ptr->next_ == 0)
        return;
    node *dptr = ptr->next_;
    ptr->next_ = ptr->next_->next_;
    delete dptr;
}
```

빈 리스트면 즉시 return합니다. 값이 여러 번 있다면 앞에서 처음 만나는 노드 하나만 삭제합니다.

### 첫 노드를 삭제: Delete(2)

```text
전: lst_ ---> [2] ---> [3] ---> [5] ---> 0
               ^
               ptr

1. lst_ = lst_->next_
   lst_ -----------> [3] ---> [5] ---> 0
   ptr ----> [2] ----^

2. delete ptr
   [2]의 메모리 해제

후: lst_ ---> [3] ---> [5] ---> 0
```

lst_를 먼저 다음 노드로 옮겨야 나머지 리스트의 시작 주소를 보존할 수 있습니다. 노드가 하나뿐이면 lst_는 0이 됩니다.

### 중간 노드를 삭제: Delete(3)

```text
전: [2] ---> [3] ---> [5] ---> 0
      ^        ^
      ptr      dptr

1. ptr를 삭제할 노드 바로 앞에 둔다.
2. dptr에 삭제할 노드의 주소를 따로 보관한다.
3. [2]의 next_를 [3]의 next_, 즉 [5]로 바꾼다.

    [2] ------------> [5] ---> 0
    dptr ---> [3] ----^

4. delete dptr로 [3]의 메모리를 해제한다.

후: [2] ---> [5] ---> 0
```

`ptr->next_->next_`는 “ptr의 다음 노드에서, 다시 그 다음 노드의 주소”라는 뜻입니다. dptr가 필요한 이유는 연결을 바꾼 뒤에도 삭제할 노드의 주소를 기억해야 하기 때문입니다.

마지막 노드를 삭제할 때는 이전 노드의 next_가 0이 됩니다. 없는 값은 ptr의 next_가 0이 될 때까지 찾고 그대로 종료합니다. `delete`는 노드의 메모리를 해제하며 주변 연결을 자동으로 고쳐 주지는 않습니다. 그래서 연결 수정이 먼저입니다.


## 9. main(): 객체 생성부터 출력까지

```cpp
int main()
{
    list *lst = new list();
    lst->Insert(2);
    lst->Insert(3);
    lst->Insert(5);
    lst->Insert(7);
    cout << lst->GetSize();
}
```

`new list()`는 리스트 관리 객체를 만들고 그 주소를 반환합니다. 그 주소를 lst가 저장합니다. `lst->Insert(2)`는 그 객체의 Insert를 실행합니다.

```text
호출                 리스트 상태
new list()           lst_ -> 0
Insert(2)            lst_ -> [2] -> 0
Insert(3)            lst_ -> [2] -> [3] -> 0
Insert(5)            lst_ -> [2] -> [3] -> [5] -> 0
Insert(7)            lst_ -> [2] -> [3] -> [5] -> [7] -> 0
GetSize()            4 반환
cout                 4 출력 (코드에는 줄바꿈 없음)
```


## 10. 선언만 있는 Find와 원본 코드의 한계

```cpp
int Find(int key);
```

Find는 클래스 안에 선언되어 있지만 실제 함수 몸체가 없습니다. 현재 main에서는 호출하지 않습니다. 호출해서 사용하려면 정의가 필요합니다. 예를 들어 존재 여부를 반환하려는 목적이라면 아래처럼 구현할 수 있지만, 이는 설명용 제안입니다.

```cpp
int list::Find(int key)
{
    return Index(key) != -1;
}
```

```text
Find(3) -> Index(3)가 1  -> 1 != -1 -> true  -> int로 1
Find(9) -> Index(9)가 -1 -> -1 != -1 -> false -> int로 0
```

또한 헤더와 cpp에 같은 클래스 정의가 있어 현재 그대로 컴파일하면 재정의 문제가 생깁니다. 일반적으로 클래스 정의는 헤더에 두고 cpp에는 함수 구현만 둡니다. 주석 처리된 과거 Insert/Delete 예시는 멤버 이름과 반환형 등이 실행 코드와 다르므로 그대로 복사해서 쓰면 안 됩니다.

현재 클래스에는 남은 노드를 해제하는 소멸자가 없고, main에서 new로 만든 list 객체도 직접 해제하지 않습니다. `delete lst`만 추가해도 노드 전체가 자동으로 해제되는 것은 아닙니다. 소멸자에서 각 노드를 순회하며 해제하는 처리가 필요합니다. 이 문서를 만들면서 원본 실행 코드를 수정하지는 않았습니다.

## 11. 함수별 소요 시간

n은 저장된 노드 개수입니다. O(n)은 노드 수가 늘수록 방문할 노드도 늘 수 있다는 뜻입니다.

| 함수 | 시간 | 이유 |
| --- | --- | --- |
| node 생성자 / list 생성자 | O(1) | 정해진 수의 멤버를 초기화한다. |
| GetSize | O(n) | 모든 노드를 센다. |
| GetAt | 최악 O(n) | 첫 노드부터 원하는 위치까지 이동한다. |
| Index | 최악 O(n) | 값이 없으면 끝까지 찾는다. |
| Insert | 최악 O(n) | 위치를 찾는 데 시간이 든다. 위치를 찾은 뒤 연결 수정은 O(1)이다. |
| Delete | 최악 O(n) | 삭제할 값을 찾는다. 찾은 뒤 연결 수정과 노드 하나의 해제는 O(1)이다. |

처음 연결 리스트를 읽을 때는 매 줄마다 “지금 포인터가 어느 노드를 가리키나?”와 “지금 바꾸는 것은 값인가, 주소인가?”를 확인하면 좋습니다.
