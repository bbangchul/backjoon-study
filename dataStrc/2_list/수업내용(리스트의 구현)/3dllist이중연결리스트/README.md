# 이중 연결 리스트: 코드와 그림으로 이해하기

> 2026-10-30 실행 검토: 클래스 정의는 헤더에만 둡니다. `Insert`의 맨 앞 삽입 조건을 `item <= head_->data_`로 수정하여 첫 값과 같은 값도 안전하게 삽입합니다. `#pragma once` 없이 컴파일·실행을 확인했습니다. 아래 원본 코드와 오류 설명 중 이 수정에 해당하는 부분은 수정 전 동작을 설명합니다.

이 문서는 같은 폴더의 `dllist.cpp`, `dllist.h`를 설명합니다. 함수별 코드 블록은 현재 소스의 실제 코드이며, 포인터가 바뀌는 순간을 그림으로 나누어 설명합니다. 이 구현은 정수를 오름차순으로 저장합니다.

## 1. 이중은 양방향이라는 뜻이다

각 노드에 이전 노드 주소 prev_와 다음 노드 주소 next_가 있습니다. 그림의 `<-->`는 서로의 주소를 저장한 두 방향 연결을 줄여 표현한 것입니다.

```text
             head_                  tail_
               |                      |
               v                      v
0 <---------- [2] <----> [3] <----> [5] ----------> 0
```

처음과 끝이 이어진 원형 리스트가 아닙니다. 마지막 5의 next_는 0이고, 첫 2의 prev_는 0입니다. tail_에서 next_로 이동하면 head_가 아니라 0에 도달합니다. tail_에서 prev_를 따라가면 `5 → 3 → 2`로 역방향 이동할 수 있습니다.

각 노드의 실제 내용은 다음과 같습니다.

```text
+-------------------+  +-------------------+  +-------------------+
| prev_ = 0         |  | prev_ = 2의 주소   |  | prev_ = 3의 주소   |
| data_ = 2         |  | data_ = 3         |  | data_ = 5         |
| next_ = 3의 주소  |  | next_ = 5의 주소  |  | next_ = 0         |
+-------------------+  +-------------------+  +-------------------+
```

head_와 tail_은 별도의 노드가 아닙니다. 기존 노드를 가리키는 두 포인터입니다. 데이터가 하나면 둘 다 같은 노드를 가리킵니다. 데이터가 없으면 둘 다 0입니다.

| 표현 | 의미 |
| --- | --- |
| `dlnode *ptr` | dlnode의 주소를 저장하는 포인터 변수 선언 |
| `ptr->data_` | ptr가 가리키는 노드의 정수 값 |
| `ptr->next_` | 그 노드가 저장한 다음 노드 주소 |
| `ptr->prev_` | 그 노드가 저장한 이전 노드 주소 |
| `ptr = ptr->next_` | 다음 노드 주소를 ptr에 대입하여 탐색 위치 이동 |
| `ptr->prev_->next_` | ptr의 이전 노드에 있는 next_ 멤버 |
| `ptr == 0` | ptr가 어떤 노드도 가리키지 않는 상태인지 검사 |

포인터에 저장된 0은 노드가 없다는 뜻이고, data_에 저장된 0은 실제 정수 값입니다. 현대 C++에서는 널 포인터를 `nullptr`로 표현하기도 합니다.

## 2. dlnode 생성자: 앞뒤 주소와 값을 저장

```cpp
    dlnode(int d, dlnode *p = 0, dlnode *n = 0)
    {
        prev_ = p;
        next_ = n;
        data_ = d;
    }
```

인수 순서는 **값, 이전 노드 주소, 다음 노드 주소**입니다. p와 n은 생략하면 0입니다.

```text
new dlnode(3, p, n)

기존 [2]                새 노드                    기존 [5]
  ^                 +-----------------+              ^
  +-----------------| prev_ = p       |              |
                    | data_ = 3       |              |
                    | next_ = n       |--------------+
                    +-----------------+
```

중요한 점은 이 생성자가 **새 노드 자신의 멤버만** 설정한다는 것입니다. 기존 `[2]`의 next_나 기존 `[5]`의 prev_는 자동으로 바뀌지 않습니다. Insert에서 그 두 연결도 따로 수정해야 완전한 양방향 연결이 됩니다.

`new dlnode(2)`는 `[prev_=0 | data_=2 | next_=0]`인 독립된 노드를 만듭니다.


## 3. dllist 생성자: 시작과 끝을 비워 두기

```cpp
dllist::dllist()
{
    head_ = 0;
    tail_ = 0;
}
```

아직 노드가 없으므로 첫 노드 주소도 마지막 노드 주소도 없습니다.

```text
dllist 객체
+-----------+
| head_ = 0 |
| tail_ = 0 |
+-----------+
```

이후 첫 삽입에서는 같은 새 노드의 주소를 head_와 tail_ 모두에 저장합니다.


## 4. Insert(item): 네 가지 위치에 삽입

```cpp
void dllist::Insert(int item)
{
    // 1. 빈 리스트: 새 노드 하나가 첫 노드이자 마지막 노드가 된다.
    if (head_ == 0)
    {
        head_ = new dlnode(item); // 새 노드를 만들고 그 주소를 head_에 저장
        tail_ = head_;
        return;
    }
    // 2. 첫 값보다 작으면 맨 앞에 삽입한다.
    if (item < head_->data_)
    {
        dlnode *ptr = new dlnode(item, 0, head_); // 새 노드의 next_는 기존 첫 노드
        head_->prev_ = ptr;                       // 기존 첫 노드의 이전 노드를 새 노드로 연결
        head_ = ptr;                              // 리스트의 시작 위치를 새 노드로 변경
        return;
    }
    // 3. 마지막 값보다 크면 맨 뒤에 삽입한다.
    if (tail_->data_ < item)
    {
        dlnode *ptr = new dlnode(item, tail_, 0); // 새 노드의 prev_는 기존 마지막 노드
        tail_->next_ = ptr;                       // 기존 마지막 노드에서 새 노드로 연결
        tail_ = ptr;                              // 리스트의 끝 위치를 새 노드로 변경
        return;
    }
    // 4. item 이상인 첫 노드를 찾아 그 노드 바로 앞에 삽입한다.
    // ptr은 탐색용 포인터이므로 이동해도 head_는 바뀌지 않는다.
    // 주의: item이 첫 노드의 값과 같으면 ptr->prev_가 0이어서
    // 아래 ptr->prev_->next_에서 잘못된 메모리 접근이 발생한다.
    dlnode *ptr = head_;
    while (ptr->data_ < item)
        ptr = ptr->next_;
    // 삽입 전: 이전 노드 ⇄ ptr
    // 삽입 후: 이전 노드 ⇄ nptr ⇄ ptr
    dlnode *nptr = new dlnode(item, ptr->prev_, ptr);
    ptr->prev_->next_ = nptr; // 이전 노드의 next_를 새 노드로 변경
    ptr->prev_ = nptr;        // ptr의 prev_를 새 노드로 변경
}
```

삽입 위치에 따라 빈 리스트, 맨 앞, 맨 뒤, 중간으로 나뉩니다. 각 경우의 return은 그 함수 호출을 종료하므로 뒤쪽 삽입 코드는 실행하지 않습니다.

### 경우 A: 빈 리스트에 Insert(2)

```text
전: head_ -> 0, tail_ -> 0

1. head_ = new dlnode(2)
2. tail_ = head_

후:         head_   tail_
              |       |
              +---+---+
                  v
           0 <-- [2] --> 0
```

tail_에 head_의 주소 값을 복사합니다. 노드를 두 개 만드는 것이 아닙니다.

### 경우 B: [3] <-> [5] 앞에 Insert(2)

조건은 `item < head_->data_`입니다.

```text
전: head_ -> [3] <--> [5] <- tail_

1. new dlnode(2, 0, head_)
   새 [2]의 prev_ = 0
   새 [2]의 next_ = 기존 [3] 주소

   ptr -> [2] ---> [3] <--> [5]
                    ^
                    head_ (아직 [3])

2. head_->prev_ = ptr
   기존 [3]의 prev_를 새 [2]로 변경

   ptr -> [2] <--> [3] <--> [5]

3. head_ = ptr
   리스트의 시작점을 새 노드로 변경

후: 0 <-- [2] <--> [3] <--> [5] --> 0
           ^                ^
           head_            tail_
```

기존 마지막 노드는 그대로이므로 tail_은 바뀌지 않습니다.

### 경우 C: [2] <-> [3] 뒤에 Insert(5)

조건은 `tail_->data_ < item`입니다.

```text
전: head_ -> [2] <--> [3] <- tail_

1. new dlnode(5, tail_, 0)
   새 [5]의 prev_ = 기존 [3] 주소
   새 [5]의 next_ = 0

   [2] <--> [3] <--- [5] <- ptr

2. tail_->next_ = ptr
   기존 [3]의 next_를 새 [5]로 변경

   [2] <--> [3] <--> [5]

3. tail_ = ptr
   마지막 위치를 새 [5]로 변경

후: 0 <-- [2] <--> [3] <--> [5] --> 0
           ^                ^
           head_            tail_
```

기존 첫 노드는 그대로이므로 head_은 바뀌지 않습니다.

### 경우 D: [2] <-> [5] 사이에 Insert(3)

단일 연결 리스트에서는 ptr를 삽입할 위치의 직전 노드에 뒀지만, 여기서는 ptr를 **새 노드가 들어갈 자리의 다음 노드**에 둡니다. ptr의 prev_로 이전 노드를 찾을 수 있기 때문입니다.

```text
1. ptr = head_ -> [2]
   2 < 3 이므로 다음으로 이동

2. ptr -> [5]
   5 < 3 은 거짓이므로 여기서 멈춤

현재: [2] <--> [5]
                ^
                ptr
```

새 노드의 양쪽 주소를 먼저 설정합니다.

```text
3. nptr = new dlnode(3, ptr->prev_, ptr)

   새 [3]의 prev_ -> [2]
   새 [3]의 next_ -> [5]
   기존 [2]와 [5]의 연결은 아직 그대로
```

이제 기존 이웃 노드들의 주소를 바꿉니다.

```text
4. ptr->prev_->next_ = nptr
   ptr는 [5]
   ptr->prev_는 [2]
   따라서 [2]의 next_를 새 [3]으로 설정

5. ptr->prev_ = nptr
   [5]의 prev_를 새 [3]으로 설정

후: 0 <-- [2] <--> [3] <--> [5] --> 0
                    ^       ^
                    nptr    ptr
```

순서도 중요합니다. 4번에서 ptr->prev_는 기존 이전 노드 `[2]`여야 합니다. 먼저 5번을 실행하면 ptr->prev_가 새 노드로 바뀌어서 같은 표현이 다른 노드를 가리키게 됩니다.

### 현재 원본의 중복 삽입 오류

첫 노드 값과 같은 값을 넣으면 문제가 생깁니다. `[2] <-> [3] <-> [5]`에 Insert(2)를 실행한다고 해 봅시다.

```text
2 < head_의 2 ? 거짓 -> 맨 앞 처리 건너뜀
5 < 2 ? 거짓        -> 맨 뒤 처리 건너뜀
ptr = head_          -> ptr는 첫 [2]
ptr의 2 < 2 ? 거짓  -> 이동 없이 멈춤
ptr->prev_ = 0
ptr->prev_->next_ 접근 -> 없는 노드에 접근하는 오류
```

노드가 하나인 상태에서 같은 값을 다시 넣어도 같은 문제가 있습니다. 새 노드를 할당한 뒤 잘못된 접근을 하므로 정상적인 삽입 결과를 얻을 수 없습니다.

학습용으로 첫 분기를 `if (item <= head_->data_)`로 바꾸면 첫 값과 같은 값도 맨 앞 분기에서 처리할 수 있습니다. 이는 수정 방법의 예시이며 원본에는 적용하지 않았습니다. 그 외 중간에 있는 값과 같은 값은 해당 기존 값 앞에 새 노드가 들어갑니다.

정상 분기에서는 중간 탐색 전에 item이 마지막 값보다 큰 경우를 이미 처리했기 때문에 탐색 중 item 이상인 노드를 만날 수 있습니다. Delete의 탐색과 달리 while 안에 ptr != 0이 없는 이유는 이 앞선 분기와 정렬 상태를 전제로 하기 때문입니다.


## 5. Delete(value): 찾고, 양쪽 연결을 수정하고, 해제

```cpp
void dllist::Delete(int value)
{
    // 첫 노드부터 next_를 따라 이동하며 삭제할 노드를 찾는다.
    dlnode *ptr = head_;
    while (ptr != 0 && ptr->data_ != value)
        ptr = ptr->next_;
    if (ptr == 0) // 값이 없음
        return;

    // 앞쪽 연결을 수정해서 삭제할 노드를 건너뛴다.
    if (ptr->prev_ == 0) // 맨 앞 노드
        head_ = ptr->next_;
    else
        ptr->prev_->next_ = ptr->next_;

    // 뒤쪽 연결도 수정한다. 양방향 연결을 모두 바꿔야 한다.
    if (ptr->next_ == 0) // 맨 뒤 노드
        tail_ = ptr->prev_;
    else
        ptr->next_->prev_ = ptr->prev_;

    // 노드가 하나뿐이었다면 위 과정에서 head_와 tail_이 모두 0이 된다.
    delete ptr; // 연결에서 제외한 노드의 메모리를 해제한다.
}
```

삭제 과정은 세 단계입니다. 먼저 값을 찾고, 이웃 노드의 연결을 바꾸고, 마지막에 해당 노드의 메모리를 해제합니다. 같은 값이 여러 번 있으면 첫 번째 노드 하나만 삭제합니다.

### 단계 1: 삭제할 노드 찾기

```text
Delete(3)

head_ -> [2] <--> [3] <--> [5]
          ^
          ptr 시작

2 != 3 이므로 ptr = ptr->next_

head_ -> [2] <--> [3] <--> [5]
                  ^
                  ptr (값을 찾았으므로 정지)
```

없는 값을 찾는 경우는 다음과 같습니다.

```text
Delete(9): ptr -> [2] -> [3] -> [5] -> 0
                                      ^
                                      ptr 최종 상태

마지막 [5]의 next_가 0이므로 ptr도 0이 됨
while 종료 -> if (ptr == 0) return
```

범위를 벗어난 노드에 접근하는 것이 아닙니다. 마지막 노드에 저장된 next_ 값 0을 읽어 ptr에 넣는 것입니다. `ptr != 0 && ptr->data_ != value`에서 왼쪽이 거짓이면 오른쪽을 검사하지 않으므로 ptr가 0일 때 data_를 읽지 않습니다. 빈 리스트도 처음부터 ptr가 0이라 바로 종료합니다.

### 단계 2: 중간 노드의 앞뒤 연결 수정

Delete(3)에서 ptr는 `[3]`입니다.

```text
전: [2] <--> [3] <--> [5]
              ^
              ptr

앞쪽 수정: ptr->prev_->next_ = ptr->next_
           [2]의 next_ = [5] 주소

뒤쪽 수정: ptr->next_->prev_ = ptr->prev_
           [5]의 prev_ = [2] 주소

양쪽 수정 후:
    [2] <--------------------> [5]
    ptr -> [3] (이웃 연결에서 제외된 노드)
```

새로 연결하는 두 주소를 식으로 풀어 보면 다음과 같습니다.

```text
ptr->prev_         = 이전 노드 [2]의 주소
ptr->next_         = 다음 노드 [5]의 주소
ptr->prev_->next_  = [2] 안의 next_ 저장 공간
ptr->next_->prev_  = [5] 안의 prev_ 저장 공간
```

한쪽 연결만 고치면 정방향과 역방향 탐색 결과가 달라지거나, 해제된 노드를 따라가게 됩니다. 두 방향 모두 수정해야 합니다.

### 단계 3: 메모리 해제

```text
delete ptr

후: head_ -> [2] <--> [5] <- tail_
    [3]의 메모리는 해제됨
```

delete는 주변 노드의 주소를 자동으로 바꾸지 않습니다. 앞뒤 연결을 먼저 수정하는 이유입니다. 해제한 ptr를 다시 역참조하면 안 되며 이 함수는 이후 ptr를 사용하지 않고 끝납니다.

### 맨 앞 삭제: Delete(2)

```text
전: 0 <-- [2] <--> [3] <--> [5] --> 0
           ^
           ptr, head_

ptr->prev_ == 0 이므로 head_ = ptr->next_ -> [3]
ptr->next_ != 0 이므로 [3]의 prev_ = ptr->prev_ -> 0
delete ptr

후: 0 <-- [3] <--> [5] --> 0
           ^        ^
           head_    tail_
```

head_만 옮기고 끝내면 새 첫 노드의 prev_가 삭제된 노드를 가리킬 수 있습니다. 뒤쪽 수정도 해야 새 첫 노드의 prev_가 0이 됩니다.

### 맨 뒤 삭제: Delete(5)

```text
전: 0 <-- [2] <--> [3] <--> [5] --> 0
                            ^
                            ptr, tail_

ptr->prev_ != 0 이므로 [3]의 next_ = ptr->next_ -> 0
ptr->next_ == 0 이므로 tail_ = ptr->prev_ -> [3]
delete ptr

후: 0 <-- [2] <--> [3] --> 0
           ^        ^
           head_    tail_
```

### 하나뿐인 노드 삭제

```text
전: head_ -> [2] <- tail_
             prev_=0, next_=0

앞쪽 분기: head_ = ptr->next_ -> 0
뒤쪽 분기: tail_ = ptr->prev_ -> 0
delete ptr

후: head_=0, tail_=0 (빈 리스트)
```

앞쪽 검사와 뒤쪽 검사가 각각 별도의 if인 이유도 여기서 드러납니다. 하나뿐인 노드는 첫 노드이자 마지막 노드이므로 두 처리가 모두 필요합니다.


## 6. Print(): 앞에서 뒤로 출력

```cpp
void dllist::Print()
{
    for (dlnode *ptr = head_; ptr != 0; ptr = ptr->next_)
        cout << ptr->data_ << " ";
    cout << endl;
}
```

for문의 세 부분은 시작 위치, 계속할 조건, 다음 위치로 이동입니다.

```text
시작: dlnode *ptr = head_
조건: ptr != 0
이동: ptr = ptr->next_
```

각 반복에서는 현재 노드의 값을 출력하고 공백 하나를 붙입니다.

```text
head_ -> [2] <--> [3] <--> [5] -> 0
          ^        ^        ^
          1회      2회      3회

1회: 2 출력 -> 다음 [3]
2회: 3 출력 -> 다음 [5]
3회: 5 출력 -> 다음 0
종료: endl로 줄바꿈

출력: 2 3 5
```

실제로 각 숫자 뒤에 공백이 하나씩 붙습니다. 빈 리스트면 숫자는 출력하지 않고 줄바꿈만 출력합니다. ptr가 이동할 뿐 head_와 tail_은 그대로입니다.


## 7. PrintReverse(): 뒤에서 앞으로 출력

```cpp
void dllist::PrintReverse()
{
    for (dlnode *ptr = tail_; ptr != 0; ptr = ptr->prev_)
        cout << ptr->data_ << " ";
    cout << endl;
}
```

Print와 구조는 같고, 시작을 tail_로 하고 이동을 prev_로 합니다.

```text
0 <- [2] <--> [3] <--> [5] <- tail_
      ^        ^        ^
      3회      2회      1회

1회: 5 출력 -> 이전 [3]
2회: 3 출력 -> 이전 [2]
3회: 2 출력 -> 이전 0
종료: 줄바꿈

출력: 5 3 2
```

역방향으로 출력한다고 노드의 실제 배치를 뒤집는 것은 아닙니다. 같은 연결을 반대 방향으로 읽습니다. 첫 노드의 prev_가 0이므로 거기서 끝납니다.


## 8. main(): 입력, 삽입, 삭제, 양방향 출력

```cpp
int main()
{
    dllist lst; // 포인터가 아닌 dllist 객체. 생성자가 호출되어 빈 리스트가 된다.
    int v;      // 사용자가 입력한 값을 잠시 저장한다.

    // 정수 7개를 입력받아 정렬된 위치에 각각 삽입한다.
    for (int i = 0; i < 7; i++)
    {
        cin >> v;
        lst.Insert(v);
    }
    // 정수 3개를 입력받아 해당 값의 노드를 각각 삭제한다.
    for (int i = 0; i < 3; i++)
    {
        cin >> v;
        lst.Delete(v);
    }
    lst.Print();        // 남은 값을 앞에서 뒤로 출력
    lst.PrintReverse(); // 남은 값을 뒤에서 앞으로 출력
    // 현재 클래스에는 소멸자가 없어 남은 노드를 직접 해제하는 처리는 없다.
}
```

여기의 lst는 `dllist lst;`로 선언한 **객체 자체**입니다. 단일 연결 리스트 예제의 `list *lst`와 달리 포인터가 아닙니다. 그래서 `lst.Insert(v)`처럼 점을 사용합니다.

먼저 정수 7개를 읽어 각각 삽입합니다. 그다음 정수 3개를 읽어 각각 삭제할 값으로 사용합니다. 총 10개의 정수가 필요하며 공백이나 줄바꿈으로 구분할 수 있습니다.

예시 입력은 첫 값과 같은 값을 중복 삽입하는 원본의 오류를 피한 예입니다.

```text
5 2 7 3 9 1 6
3 9 1
```

처음 7개를 넣는 과정:

```text
Insert(5): [5]
Insert(2): [2] <-> [5]
Insert(7): [2] <-> [5] <-> [7]
Insert(3): [2] <-> [3] <-> [5] <-> [7]
Insert(9): [2] <-> [3] <-> [5] <-> [7] <-> [9]
Insert(1): [1] <-> [2] <-> [3] <-> [5] <-> [7] <-> [9]
Insert(6): [1] <-> [2] <-> [3] <-> [5] <-> [6] <-> [7] <-> [9]
```

이후 3개를 삭제하는 과정:

```text
Delete(3): [1] <-> [2] <-> [5] <-> [6] <-> [7] <-> [9]
Delete(9): [1] <-> [2] <-> [5] <-> [6] <-> [7]
Delete(1): [2] <-> [5] <-> [6] <-> [7]
```

정상적인 클래스 정의 구성에서 이 예시를 실행하면 출력은 다음과 같습니다. 각 줄 마지막 숫자 뒤에는 코드에 따른 공백도 있습니다.

```text
2 5 6 7
7 6 5 2
```


## 9. 선언만 있거나 주석 처리된 함수

```cpp
// int GetSize();
// int GetAt(int position);
// int Index(int value);
int Find(int key);
```

GetSize, GetAt, Index는 현재 클래스에서 주석 처리되어 있고 구현도 없습니다. 이 파일의 함수처럼 호출해서 사용할 수 있는 상태가 아닙니다. Find는 선언은 있지만 정의가 없습니다. 현재 main은 Find를 호출하지 않지만, 사용하려면 구현해야 합니다. 이름만 보고 반환값을 확정할 수는 없습니다.

존재 여부를 반환하는 Find를 추가하려는 경우의 학습용 예시는 다음과 같습니다. 원본 파일에는 적용하지 않았습니다.

```cpp
int dllist::Find(int key)
{
    dlnode *ptr = head_;
    while (ptr != 0)
    {
        if (ptr->data_ == key)
            return 1;
        ptr = ptr->next_;
    }
    return 0;
}
```

```text
Find(5): [2] -> [3] -> [5]       -> 발견 -> 1
Find(9): [2] -> [3] -> [5] -> 0  -> 못 찾음 -> 0
```

## 10. 현재 소스 구성의 한계

dllist.h와 dllist.cpp에 같은 두 클래스가 정의되어 있어 그대로 컴파일하면 재정의 문제가 발생합니다. 보통 클래스 정의는 헤더에만 두고 cpp에는 함수 구현을 둡니다. 위 출력 예시는 이러한 소스 구성 문제를 해결한 상태에서의 동작 설명입니다.

현재 소멸자가 없어서 main 종료 시 dllist 객체 자체의 수명이 끝나더라도 동적으로 생성한 남은 노드를 순회해서 해제하지는 않습니다. `Delete`는 지정한 노드 한 개만 해제합니다. 모든 남은 노드를 정리하려면 소멸자에서 각 노드를 해제하는 처리가 필요합니다.

이 문서에서는 기존 코드의 동작과 한계를 설명했으며 실행 코드는 변경하지 않았습니다.

## 11. 함수별 소요 시간

| 함수 | 시간 | 이유 |
| --- | --- | --- |
| dlnode / dllist 생성자 | O(1) | 고정된 수의 멤버를 초기화한다. |
| Insert | 최악 O(n) | 중간 위치를 찾는 탐색이 필요하다. 맨 앞·뒤의 분기는 O(1)이다. |
| Delete | 최악 O(n) | 값의 위치를 찾는다. 노드를 찾은 후 연결 수정은 O(1)이다. |
| Print | O(n) | 모든 노드를 정방향으로 방문한다. |
| PrintReverse | O(n) | 모든 노드를 역방향으로 방문한다. |

n은 현재 노드 개수입니다. 이중 연결 리스트라고 해서 값을 찾는 과정까지 자동으로 빠른 것은 아닙니다. 이 코드의 삭제는 head_부터 값을 찾습니다. 대신 노드를 찾고 나면 prev_와 next_를 사용해 양쪽 이웃을 바로 확인할 수 있습니다.

## 12. 포인터를 이해했는지 확인하기

다음 연결에서 ptr가 `[3]`을 가리킨다고 가정해 봅시다.

```text
head_ -> [2] <--> [3] <--> [5] <- tail_
                  ^
                  ptr
```

- ptr->data_는 3입니다.
- ptr->prev_->data_는 2입니다.
- ptr->next_->data_는 5입니다.
- head_->prev_는 0입니다.
- tail_->next_는 0입니다.
- ptr를 next_로 이동시켜도 head_와 tail_은 바뀌지 않습니다.

주소를 바꿀 때마다 “어느 노드 안에 있는 멤버를 바꾸는가?”를 먼저 짚어 보면 긴 포인터 표현도 읽기 쉬워집니다.
