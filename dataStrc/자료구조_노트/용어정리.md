# 자료구조 용어 정리

리스트·큐·스택 예제에서 사용하는 용어를 중심으로 정리했습니다.

## 1. 기본 용어

| 용어 | 영어 / 코드 | 뜻 |
| --- | --- | --- |
| 자료구조 | Data Structure | 데이터를 저장하고 사용하는 방식 |
| 알고리즘 | Algorithm | 문제를 해결하는 단계와 처리 절차 |
| 원소 | Element / Item | 자료구조에 저장된 값 하나 |
| 키 | Key | 탐색·정렬의 기준이 되는 값. 현재 예제에서는 정수 값 자체 |
| 인덱스 | Index | 원소의 위치를 나타내는 번호. 배열에서는 0부터 시작 |
| 용량 | Capacity | 저장할 수 있는 최대 원소 개수 |
| 현재 개수 | Size / Count | 지금 저장된 원소 개수 |
| 삽입 | Insert | 새 원소를 넣는 작업 |
| 삭제 | Delete | 원소를 자료구조에서 제거하는 작업 |
| 탐색 | Search | 원하는 값이나 위치를 찾는 작업 |
| 순회 | Traversal | 원소들을 차례대로 방문하는 작업 |

**용량과 개수는 다릅니다.** 용량 5인 배열에 원소 3개를 넣었다면 현재 개수는 3이고 마지막 유효 인덱스는 2입니다.

```text
인덱스:   0   1   2   3   4
배열:    [2] [5] [3] [?] [?]
         유효 원소   미사용 칸
용량 = 5, 개수 = 3
```

## 2. C++와 메모리

| 용어 | 영어 / 코드 | 뜻 |
| --- | --- | --- |
| 배열 | Array | 같은 자료형의 원소를 메모리에 연속해서 저장하는 구조 |
| 구조체 | `struct` | 여러 멤버를 묶는 사용자 정의 자료형. 기본 접근 권한은 public |
| 클래스 | `class` | 데이터와 함수를 묶는 사용자 정의 자료형. 기본 접근 권한은 private |
| 객체 | Object | 클래스나 구조체 등의 자료형으로 만든 실제 대상 |
| 멤버 변수 | Member Variable | 객체가 가진 데이터. 예: storage, top, size |
| 멤버 함수 | Member Function | 객체의 데이터를 다루는 함수. 예: Push, Pop |
| 생성자 | Constructor | 객체가 만들어질 때 초기 상태를 설정하는 함수 |
| 소멸자 | Destructor / `~Stack()` | 객체의 수명이 끝날 때 호출되는 함수. 동적 메모리 정리 등에 사용 |
| 포인터 | Pointer / `node *ptr` | 다른 대상의 메모리 주소를 저장하는 변수 |
| 주소 | Address / `&obj` | 대상이 메모리에 있는 위치 |
| 역참조 | Dereference / `*ptr` | 포인터가 가리키는 대상에 접근하는 것 |
| 널 포인터 | Null Pointer / `nullptr` | 아무 대상도 가리키지 않는 포인터. 수업 코드에서는 0으로 표현 |
| 동적 할당 | Dynamic Allocation / `new` | 실행 중 필요한 객체나 배열의 저장 공간을 확보하는 것 |
| 메모리 해제 | `delete`, `delete[]` | 동적으로 할당한 공간을 반환하는 것 |
| 메모리 누수 | Memory Leak | 필요한 동적 메모리를 해제하지 못해 공간이 남는 문제 |
| 자기참조 | Self-reference | 노드가 같은 종류의 다른 노드 주소를 멤버로 저장하는 구조 |
| 연산자 오버로딩 | Operator Overloading | 사용자 정의 자료형에 +, << 등의 연산 동작을 정의하는 것 |

```cpp
Stack stack;             // 객체 생성
stack.Push(10);          // 객체의 멤버 함수 호출: .
Stack *ptr = new Stack;  // 동적 객체 생성, 주소 저장
ptr->Push(20);           // 포인터를 통한 멤버 함수 호출: ->
delete ptr;              // 소멸자 호출 후 객체 공간 해제

int *arr = new int[5];
delete[] arr;            // new[]로 만든 배열은 delete[]로 해제
```

## 3. 리스트와 연결 노드

| 용어 | 영어 / 코드 | 뜻 |
| --- | --- | --- |
| 리스트 | List | 원소를 순서 있게 저장하는 자료구조. 반드시 정렬되어야 하는 것은 아님 |
| 정렬된 리스트 | Ordered List | 값을 정렬 기준에 맞춰 저장하는 리스트. 현재 예제는 오름차순 |
| 배열 리스트 | Array List | 배열에 원소를 저장하는 리스트 |
| 연결 리스트 | Linked List | 노드들을 주소로 연결한 리스트 |
| 노드 | Node | 값과 연결 정보를 담는 단위 |
| 단일 연결 리스트 | Singly Linked List | 각 노드가 다음 노드의 주소를 저장하는 리스트 |
| 이중 연결 리스트 | Doubly Linked List | 각 노드가 이전·다음 노드의 주소를 모두 저장하는 리스트 |
| 머리 | Head / head_, lst_ | 첫 노드를 가리키는 포인터 |
| 꼬리 | Tail / tail_ | 마지막 노드를 가리키는 포인터 |
| 다음 노드 | Next / next_, nxt_ | 다음 노드의 주소를 담는 멤버 |
| 이전 노드 | Previous / prev_ | 이전 노드의 주소를 담는 멤버 |

```text
단일 연결 리스트
head --> [2|next] --> [3|next] --> [5|0]

이중 연결 리스트
         head                  tail
           |                     |
           v                     v
0 <-- [prev|2|next] <--> [prev|5|next] --> 0
```

| 함수 이름 | 의미 |
| --- | --- |
| GetSize | 현재 원소 개수 반환 |
| GetAt | 지정한 인덱스의 값 반환 |
| Index | 지정한 값의 위치 반환 |
| Find | 값이 존재하는지 확인 |
| Insert / Delete | 원소 삽입 / 삭제 |

`GetAt(2)`의 2는 **위치**, `Index(2)`의 2는 **찾을 값**입니다.

## 4. 큐

| 용어 | 영어 / 코드 | 뜻 |
| --- | --- | --- |
| 큐 | Queue | 먼저 넣은 원소를 먼저 꺼내는 자료구조 |
| 선입선출 | FIFO: First In, First Out | 먼저 들어온 원소가 먼저 나가는 규칙 |
| 앞쪽 | Front / front_ | 다음에 삭제할 위치 또는 첫 노드 |
| 뒤쪽 | Rear / rear_ | 배열 큐에서는 다음 삽입 위치, 포인터 큐에서는 마지막 노드 |
| 큐 삽입 | Enqueue / InsertQ | 큐 뒤에 원소를 넣는 작업 |
| 큐 삭제 | Dequeue / DeleteQ | 큐 앞의 원소를 꺼내는 작업 |
| 환형 큐 | Circular Queue | 배열 끝에 도달하면 처음으로 돌아가 공간을 재사용하는 큐 |
| 나머지 연산 | Modulo / `%` | 나눗셈의 나머지를 구하는 연산. 환형 큐의 인덱스 순환에 사용 |
| 우선순위 큐 | Priority Queue | 들어온 순서보다 우선순위에 따라 원소를 꺼내는 자료구조 |
| 퍼사드 | Facade | 내부의 여러 동작을 단순한 외부 인터페이스로 감싸는 방식 |
| 불변식 | Invariant | 자료구조가 올바르게 동작하는 동안 유지해야 하는 규칙 |

```text
삽입: 2 -> 5 -> 3

DeleteQ <-- [2] [5] [3] <-- InsertQ
            front   rear

삭제 순서: 2 -> 5 -> 3
```

- 현재 환형 큐는 한 칸을 비워 빈 상태와 가득 찬 상태를 구분합니다.
- 현재 우선순위 큐는 작은 값을 먼저 꺼냅니다.
- queue20의 불변식: 뒤쪽 큐 qb에 값이 있으면 앞쪽 큐 qa는 가득 차 있어야 합니다.

## 5. 스택

| 용어 | 영어 / 코드 | 뜻 |
| --- | --- | --- |
| 스택 | Stack | 마지막에 넣은 원소를 먼저 꺼내는 자료구조 |
| 후입선출 | LIFO: Last In, First Out | 나중에 들어온 원소가 먼저 나가는 규칙 |
| 스택 삽입 | Push | 스택 위에 원소를 넣는 작업 |
| 스택 삭제 | Pop | 스택 위의 원소를 꺼내고 제거하는 작업 |
| 맨 위 조회 | Top / Peek | 맨 위의 값을 제거하지 않고 읽는 작업 |
| 배열 스택의 top | `int top` | 다음 삽입 위치. 현재 원소 개수와 같음 |
| 포인터 스택의 top | `node *top` | 마지막으로 삽입한 노드의 주소 |
| 빈 상태 검사 | IsEmpty | 원소가 없는지 확인 |
| 가득 찬 상태 검사 | IsFull | 정해진 용량을 모두 사용했는지 확인 |
| 오버플로 | Stack Overflow | 스택의 허용 용량을 넘기려는 상황 |
| 언더플로 | Stack Underflow | 빈 스택에서 원소를 꺼내려는 상황 |
| WFF | Well-Formed Formula | 잘 갖춰진 식. 현재 예제에서는 괄호의 짝과 중첩이 올바른지 검사 |

```text
Push(2), Push(5), Push(3)

      +---+
      | 3 | <-- Top 조회 / Pop 삭제
      +---+
      | 5 |
      +---+
      | 2 |
      +---+

삭제 순서: 3 -> 5 -> 2
```

배열 스택의 마지막 값은 `storage[top - 1]`입니다.
`Top()`은 값을 유지하고, `Pop()`은 값을 제거합니다.
현재 코드에서 빈 스택의 Top과 Pop은 0을 반환하므로 실제 데이터 0과 구분하려면 IsEmpty를 확인합니다.

## 6. 알고리즘과 복잡도

| 용어 | 영어 / 표기 | 뜻 |
| --- | --- | --- |
| 정렬 | Sorting | 값을 기준에 따라 순서대로 배치하는 작업 |
| 오름차순 | Ascending Order | 작은 값부터 큰 값 순서 |
| 내림차순 | Descending Order | 큰 값부터 작은 값 순서 |
| 버블 정렬 | Bubble Sort | 이웃한 값을 비교하고 교환하는 정렬 |
| 병합 정렬 | Merge Sort | 나눠서 정렬한 부분들을 다시 합치는 정렬 |
| 재귀 | Recursion | 함수가 자기 자신을 호출하는 방식 |
| 분할 정복 | Divide and Conquer | 문제를 작은 문제로 나누고 해결 결과를 합치는 방식 |
| 시간복잡도 | Time Complexity | 입력 크기에 따라 연산량이 어떻게 증가하는지 나타내는 것 |
| 공간복잡도 | Space Complexity | 입력 크기에 따라 필요한 메모리가 어떻게 증가하는지 나타내는 것 |
| 빅오 | Big O / O(...) | 증가하는 비용의 점근적 상한을 나타내는 표기 |
| 최악의 경우 | Worst Case | 같은 입력 크기에서 비용이 가장 큰 경우 |

| 표기 | 의미 | 현재 예제 |
| --- | --- | --- |
| O(1) | 입력 크기가 커져도 비용이 일정한 수준 | 스택 Top, Push, Pop의 기본 연산 |
| O(log n) | 문제 범위를 반복해서 줄이는 수준 | 이진 탐색의 비교 횟수(현재 리스트 예제는 순차 탐색) |
| O(n) | 원소 수에 비례하는 수준 | 리스트 순회, 배열 리스트 삽입·삭제 |
| O(n log n) | 선형 작업을 로그 수준의 단계로 수행 | 병합 정렬 |
| O(n²) | 원소 수의 제곱에 비례하는 수준 | 현재 버블 정렬 |

n은 입력 또는 원소 개수입니다. Big O는 정확한 실행 시간을 초 단위로 나타내는 표기가 아닙니다.

## 7. 자주 헷갈리는 구분

| 구분 | 차이 |
| --- | --- |
| 용량 / 개수 | 최대 저장 공간 / 현재 저장된 원소 수 |
| 인덱스 / 값 | 저장 위치 / 그 위치에 담긴 데이터 |
| 포인터 / 노드 | 주소를 저장하는 변수 / 주소가 가리키는 실제 객체 |
| Top / Pop | 조회만 함 / 조회하고 제거함 |
| 배열 top / 포인터 top | 다음 삽입 인덱스 / 마지막 노드 주소 |
| 큐 / 스택 | FIFO / LIFO |
| 삭제 / 메모리 해제 | 자료구조에서 제외 / 할당된 공간 반환. 배열 원소 삭제는 보통 공간을 해제하지 않음 |
| empty / full | 원소가 없음 / 용량을 모두 사용함. 용량 0인 배열 스택은 둘 다 true 가능 |
