# 시험 대비 실행 검토 (2026-10-30)

`main`이 있는 C++ 파일 43개를 각각 빌드하고 총 73회 실행했습니다.
`clang++ -std=c++17 -Wall -Wextra -fsanitize=address,undefined`로 검사했습니다.
샘플 입력에서 sanitizer 오류는 없었습니다. 전체 입력 범위를 보장하는 검사는 아닙니다.
문자열 뒤집기 3개 예제의 30바이트 초과 입력은 의도된 오류 메시지와 종료 코드 1을 확인했습니다.
나머지 70회 실행은 종료 코드 0입니다. 추가로 배열/연결 리스트의 빈 리스트, 음수·범위 밖 인덱스, 중복 삽입·삭제를 assertion으로 확인했습니다.

## 수정 내용

- 연결 리스트, 배열 리스트, 배열 큐 I, 포인터 큐: 헤더와 cpp의 중복 클래스 정의 제거.
- 연결 리스트: 구현의 `nxt_`를 헤더와 같은 `next_`로 통일, `GetAt`의 잘못된 인덱스 접근 방지.
- 배열 리스트: `GetAt`의 음수 인덱스 접근 방지.
- 이중 연결 리스트: 맨 앞 값과 동일한 값을 삽입할 때 널 포인터에 접근하던 조건 수정.
- 앞서 추가했던 `dllist.h`의 `#pragma once` 제거.

## 직접 실행하는 방법

프로젝트 최상위 폴더에서 실행합니다. **main이 여러 개이므로 전체 cpp를 한 번에 묶어서 컴파일하지 않습니다.**
대부분은 해당 cpp 하나로 실행할 수 있습니다.

```sh
c++ -std=c++17 "실행할 파일의 경로.cpp" -o /tmp/ds_example
/tmp/ds_example
```

`4_stack`의 통합본 `main.cpp`도 각각 파일 하나만 컴파일합니다.
다음 두 원본 응용 예제는 별도 스택 구현을 함께 링크해야 합니다.

```sh
c++ -std=c++17 '4_stack/2_stackApp문자열뒤집기/reverse.cpp' '4_stack/1_arrayStack배열스택/stack.cpp' -o /tmp/ds_reverse
/tmp/ds_reverse

c++ -std=c++17 '4_stack/4_stackApp괄호검사/wff.cpp' '4_stack/3_ptrStack포인터스택/stack.cpp' -o /tmp/ds_wff
/tmp/ds_wff
```

## 입력 형식

- 좌표 예제 B10: 좌표 3쌍. B11~B14: 좌표 10쌍.
- 분수 예제: `1/2 1/3 3/4 1/4`처럼 분수 4개. 기존 가정대로 분모 0은 제외합니다.
- `dllist.cpp`: 삽입할 정수 7개, 이어서 삭제할 정수 3개.
- 우선순위 큐 정렬: 정수 7개.
- 큐 응용: 0을 제외한 정수 10개.
- 문자열 뒤집기: 영문 등 단일 바이트 문자열 한 줄, 최대 30바이트.
- 괄호 검사: 괄호 식 한 줄. 예: `({[]})`, `([)]`.
- 그 외 예제는 입력 없이 실행합니다.

B92/B93의 미사용 변수 경고는 실행을 막지 않아 유지했습니다.
현재 main에서 호출하지 않는 함수와 모든 비정상 입력까지 구현·검증한 것은 아닙니다.
