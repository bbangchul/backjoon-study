# 자료구조 정리 노트

현재 작업 폴더의 수업 예제를 기준으로 정리한 복습 노트입니다.
그림의 `?`는 미사용 배열 칸, `0`은 연결된 노드가 없는 포인터를 뜻합니다.

## 1. 전체 흐름

```text
1_Intro : 정렬           -> 값을 일정한 순서로 배치
2_list  : 리스트         -> 값을 저장하고 탐색·삽입·삭제
3_queue : 큐 (FIFO)      -> 먼저 넣은 값을 먼저 꺼냄
4_stack : 스택 (LIFO)    -> 나중에 넣은 값을 먼저 꺼냄
```

| 구분 | 리스트 | 큐 | 스택 |
| --- | --- | --- | --- |
| 삽입 위치 | 예제에서는 정렬된 위치 | 뒤쪽 rear | 위쪽 top |
| 삭제 위치 | 지정한 값의 위치 | 앞쪽 front | 위쪽 top |
| 2, 5, 3 삽입 후 | 2, 3, 5로 정렬 | 2, 5, 3 순서로 삭제 | 3, 5, 2 순서로 삭제 |

## 2. 선수지식: 배열·객체·포인터

```cpp
int arr[3] = {2, 5, 3};
// arr[0] == 2, arr[1] == 5, arr[2] == 3
```

배열 인덱스는 0부터 시작합니다. 원소가 n개이면 마지막 인덱스는 n - 1입니다.
배열의 전체 용량과 현재 저장된 원소 개수는 구분해야 합니다.

```text
용량 = 5, 현재 개수 = 3
인덱스   0   1   2   3   4
배열    [2] [5] [3] [?] [?]
        <유효 값>   <미사용>
```

| 표현 | 의미 |
| --- | --- |
| `obj.Push(2)` | 객체의 함수 호출 |
| `ptr->Push(2)` | 포인터가 가리키는 객체의 함수 호출 |
| `&obj` | 객체의 주소 |
| `*ptr` | 포인터가 가리키는 대상 |
| `new node(...)` | 노드를 동적으로 생성하고 주소 반환 |
| `delete ptr` | 동적으로 생성한 객체 해제 |
| `delete[] arr` | 동적으로 생성한 배열 해제 |

자기참조 구조는 노드가 같은 종류의 다른 노드 주소를 저장하는 구조입니다.

```text
node
+------+--------+
| data | next --+---> 다음 node
+------+--------+
```

분수 예제에서는 struct → class → 연산자 오버로딩 → 입출력 연산자로 확장합니다.
관련 코드는 `2_list/선수지식`과 `2_list/선수지식(자기참조)`에 있습니다.

## 3. 정렬 — 1_Intro

### 버블 정렬

이웃한 두 값을 비교하고 앞의 값이 더 크면 교환합니다.
한 번 왼쪽에서 오른쪽으로 훑으면 가장 큰 값이 오른쪽 끝으로 이동합니다.

```text
[5][3][8][4]
  교환
[3][5][8][4]
        교환
[3][5][4][8]  <- 가장 큰 값 8이 끝으로 이동
```

현재 `bubblesort.cpp`는 매번 전체 범위를 반복하므로 이미 정렬된 입력도 O(n²)입니다.

### 병합 정렬

배열을 반으로 나누고, 각 부분을 정렬한 뒤 작은 값부터 합칩니다.

```text
        [5 3 8 4]
         /     \
      [5 3]   [8 4]
       / \     / \
      [5][3]  [8][4]
       \ /     \ /
      [3 5]   [4 8]
         \     /
        [3 4 5 8]
```

`MergeSort`는 분할, `Merge`는 병합을 담당합니다.
시간복잡도는 O(n log n)이고, 병합용 추가 공간이 필요합니다.
현재 `mergesort.cpp`의 버퍼는 100칸이므로 사용하는 인덱스도 그 범위 안이어야 합니다.

## 4. 리스트 — 2_list

이 폴더의 리스트는 삽입할 때 오름차순을 유지합니다.

| 함수 | 역할 |
| --- | --- |
| `GetSize()` | 원소 개수 반환 |
| `GetAt(index)` | 해당 인덱스의 값 반환 |
| `Index(value)` | 해당 값의 인덱스 반환, 없으면 -1 |
| `Find(value)` | 값이 있는지 확인 |
| `Insert(value)` | 정렬된 위치에 삽입 |
| `Delete(value)` | 같은 값의 첫 원소 하나 삭제 |

### 배열 리스트

삽입할 자리 뒤의 값을 **오른쪽으로**, 삭제한 자리 뒤의 값을 **왼쪽으로** 옮깁니다.

```text
Insert(3)
[2][5][7][?]  ->  [2][5][5][7]  ->  [2][3][5][7]
                 뒤에서부터 이동     빈자리에 3 저장

Delete(3)
[2][3][5][7]  ->  [2][5][7] | [7]
                 유효 값     미사용 칸에 남은 값
```

삭제 후 마지막 칸에 값이 남아 있어도 현재 개수 밖이면 유효 데이터가 아닙니다.

### 단일 연결 리스트

노드를 따라 이동합니다. 배열처럼 연속한 메모리에 저장할 필요가 없습니다.

```text
lst_ --> [2|next] --> [5|next] --> [7|0]

Insert(3)
lst_ --> [2|next] --> [3|next] --> [5|next] --> [7|0]

Delete(3)
lst_ --> [2|next] --------------> [5|next] --> [7|0]
                     [3]은 연결에서 제외한 뒤 delete
```

삽입할 때 기존 다음 노드의 주소를 보존하고 연결을 바꿉니다.
삭제할 때는 노드를 건너뛰도록 연결한 뒤 메모리를 해제합니다.

### 이중 연결 리스트

각 노드가 이전 노드와 다음 노드의 주소를 모두 저장합니다.

```text
         head_                         tail_
           |                             |
           v                             v
0 <-- [prev|2|next] <--> [prev|3|next] <--> [prev|5|next] --> 0
```

`Print()`는 head부터 next 방향, `PrintReverse()`는 tail부터 prev 방향으로 이동합니다.
삽입·삭제 시 양쪽 연결을 모두 바꿔야 합니다. 첫 노드와 마지막 노드는 별도로 처리합니다.

## 5. 큐 — 3_queue

FIFO(First In, First Out): 먼저 넣은 값을 먼저 꺼냅니다.

```text
DeleteQ() <-- [2][5][3] <-- InsertQ(7)
              앞   뒤
```

### 배열 큐 I: 인덱스 이동

`front_`는 다음 삭제 위치, `rear_`는 다음 삽입 위치입니다.

```text
[2][5][3][?][?]   front=0, rear=3
[?][5][3][?][?]   front=1, rear=3  <- 2 삭제
```

삭제한 앞쪽 공간을 다시 사용하지 못합니다. `rear_ == MAXQ`면 삽입이 막힙니다.
빈 상태는 `front_ == rear_`입니다.

### 배열 큐 II: 값 이동

항상 `arr_[0]`에서 삭제하고, 남은 값을 왼쪽으로 옮깁니다.
앞쪽 공간을 재사용할 수 있지만 삭제에 O(n)이 걸립니다.

```text
[2][5][3][?]  -- DeleteQ() -->  [5][3][?][?]
```

### 환형 큐: 끝에서 처음으로 순환

인덱스를 `(index + 1) % MAXQ`로 갱신합니다.
현재 구현은 빈 상태와 가득 찬 상태를 구분하기 위해 한 칸을 비워 둡니다.

```text
인덱스:    0   1   2   3   4
배열:     [C] [?] [?] [A] [B]
               ^       ^
              rear    front

삭제 순서: A -> B -> C
인덱스 이동: 3 -> 4 -> 0 -> 1
```

```cpp
IsEmpty: rear_ == front_
IsFull:  (rear_ + 1) % MAXQ == front_
```

배열 100칸이면 최대 저장 개수는 99개입니다.

### 포인터 큐

```text
front_ --> [2|next] --> [5|next] --> [3|0] <-- rear_
           삭제 위치                  삽입 위치
```

뒤에 노드를 연결하고 앞에서 노드를 삭제합니다.
마지막 노드를 삭제하면 front와 rear를 모두 0으로 바꿉니다.

### 응용과 확장

- `5_queueApp큐응용`: 정수 10개를 음수 큐와 나머지 큐로 나누고 각각 입력 순서로 출력합니다. 예제는 0이 없다고 가정합니다.
- `6_priorityQueue우선순위큐`: 정렬된 연결 리스트를 이용해 작은 값을 먼저 꺼냅니다. 일반 FIFO 큐와 삭제 순서가 다릅니다.
- `7_queue20퍼사드`: 용량 10인 큐 두 개를 감싸 용량 20인 큐로 사용합니다.

```text
queue20
+-------------------------------------+
| qa: 앞쪽 최대 10개 | qb: 뒤쪽 최대 10개 |
+-------------------------------------+

삭제: qa의 첫 값 제거 -> qb의 첫 값을 qa의 뒤로 이동
규칙: qb에 값이 있으면 qa는 항상 가득 찬 상태 유지
```

## 6. 스택 — 4_stack

LIFO(Last In, First Out): 마지막에 넣은 값을 먼저 꺼냅니다.

```text
Push(2), Push(5), Push(3)

       Push / Pop
           |
           v
        +-----+
        |  3  |  <- 마지막으로 넣은 값
        +-----+
        |  5  |
        +-----+
        |  2  |
        +-----+

Pop 순서: 3 -> 5 -> 2
```

### 배열 스택

`top`은 **다음 삽입 위치**이며 현재 원소 개수와 같습니다.

```text
인덱스:   0   1   2   3   4
storage: [2] [5] [3] [?] [?]
                     ^
                    top=3
마지막 원소: storage[top - 1] == 3
```

```cpp
IsEmpty(): top == 0
IsFull():  top == size
Push(el):  storage[top++] = el;  // 저장 후 증가
Pop():     return storage[--top]; // 감소 후 읽기
Top():     return storage[top - 1]; // 삭제하지 않고 읽기
```

`Push`는 가득 찼으면 false, 성공하면 true를 반환합니다.
`Pop`과 `Top`은 빈 스택이면 0을 반환합니다. 데이터 0과 구분하려면 `IsEmpty`를 먼저 확인합니다.

### 포인터 스택

`top`은 마지막으로 삽입한 노드의 주소입니다.

```text
top --> [3|next] --> [5|next] --> [2|0]

Push(7)
top --> [7|next] --> [3|next] --> [5|next] --> [2|0]

Pop() -> 7 반환, 첫 노드 해제
top --> [3|next] --> [5|next] --> [2|0]
```

```cpp
Push: top = new node(el, top);
Pop:  기존 top 저장 -> top을 next로 이동 -> 기존 노드 delete
```

빈 상태는 `top == 0`입니다. `IsFull()`은 고정 용량 제한이 없어 항상 false를 반환합니다.
실제 메모리 할당 실패는 `new`의 예외로 처리됩니다.

### 문자열 뒤집기

문자를 입력 순서로 Push한 뒤 모두 Pop하면 역순이 됩니다.

```text
입력: h -> e -> l -> l -> o
출력: o -> l -> l -> e -> h
```

현재 예제의 용량은 30바이트입니다. 바이트를 뒤집으므로 영문 같은 단일 바이트 문자열에 사용합니다.

### WFF: 괄호 짝 검사

여는 괄호를 Push하고, 닫는 괄호가 나오면 Top과 짝을 비교한 뒤 Pop합니다.

```text
입력     스택 (왼쪽이 바닥)     처리
(        (                    Push
[        ( [                  Push
]        (                    [와 ] 일치 -> Pop
)        비어 있음             (와 ) 일치 -> Pop
```

닫는 괄호에서 스택이 비었거나 짝이 다르면 실패입니다.
입력이 끝난 뒤에도 여는 괄호가 남아 있으면 실패입니다.
현재 코드는 괄호 외의 문자를 무시하며, 빈 입력은 WFF로 판정합니다.

## 7. 시간복잡도 비교

n은 현재 원소 개수입니다. 아래는 탐색·이동 비용 기준이며 메모리 할당 비용은 별도입니다.

| 구현 | 삽입 | 삭제 | 조회 / 빈 상태 확인 |
| --- | --- | --- | --- |
| 정렬된 배열 리스트 | O(n) | 값 탐색·이동 O(n) | GetAt O(1), GetSize O(1) |
| 정렬된 단일 연결 리스트 | O(n) | 값 탐색 O(n) | GetAt O(n), GetSize O(n) |
| 정렬된 이중 연결 리스트 | 최악 O(n) | 값 탐색 O(n), 찾은 뒤 연결 변경 O(1) | 양방향 순회 O(n) |
| 배열 큐 I | O(1) | O(1) | IsEmpty O(1) |
| 배열 큐 II | O(1) | O(n) | IsEmpty O(1) |
| 환형 큐 / 포인터 큐 | O(1) | O(1) | IsEmpty O(1) |
| 현재 우선순위 큐 | O(n) | O(1) | IsEmpty O(n): GetSize가 노드를 셈 |
| 배열 스택 / 포인터 스택 | O(1) | O(1) | Top, IsEmpty O(1) |

문자열 뒤집기와 괄호 검사는 입력 길이를 m이라 할 때 시간 O(m), 추가 공간 최악 O(m)입니다.
현재 문자열 예제는 고정 용량을 사용합니다.

## 8. 현재 코드에서 주의할 점

- 일부 리스트·큐 예제는 헤더를 include하면서 같은 클래스를 cpp에도 정의하여 재정의 오류가 발생할 수 있습니다.
- 배열 리스트 `GetAt`은 음수 인덱스를 검사하지 않습니다. 단일 연결 리스트 `GetAt`은 빈 리스트나 범위 끝에서 null 접근 가능성이 있습니다.
- 이중 연결 리스트는 첫 값과 같은 값을 삽입할 때 null인 prev에 접근할 수 있습니다. `Find`는 선언만 있습니다.
- 기존 리스트·큐 일부에는 남은 동적 메모리를 해제하는 소멸자가 없습니다.
- `4_stack`의 통합 `main.cpp`는 파일 하나만 컴파일합니다. `stack.cpp`를 함께 링크하면 중복 정의가 발생합니다.

## 9. 빠른 복습

```text
배열 리스트: 삽입은 오른쪽 이동, 삭제는 왼쪽 이동
연결 리스트: 값을 옮기는 대신 연결 주소 변경
큐: front에서 삭제, rear에서 삽입
환형 큐: % 연산으로 인덱스 순환, 한 칸 비워 둠
배열 스택: top = 다음 삽입 위치
포인터 스택: top = 마지막 노드 주소
Top = 조회, Pop = 조회 + 삭제
괄호 검사: 마지막으로 연 괄호부터 먼저 닫혀야 함
```

리스트의 자세한 함수 설명은 `2_list/수업내용(리스트의 구현)`의 각 `README.md`,
스택 컴파일 방법은 [4_stack/README.md](4_stack/README.md)를 참고하면 됩니다.
